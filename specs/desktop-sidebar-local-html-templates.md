# 桌面客户端侧栏与本地 HTML 模板规格

> **状态**：服务端账号侧栏同步、受管 Logo、模板目录/包/截图/entitlement v1 已实现；桌面模板运行时、内置模板 UI、Markdown 桥接和购买渠道尚未实现。
> **Web 发布审核工作包**：Publisher 工作台、管理员审核台、免费目录、entitlement 测试和下载审计以 `specs/ai-direct-web-server-roadmap.md` 的“工作包 H”为准；它不改变模板业务数据仅存本机、Web 不运行模板的边界。
> **范围**：桌面端左侧栏自定义与账号级跨设备同步、本地 HTML 预设模板、Markdown 导入导出、模板扩展与市场分发。
> **参考原型**：仓库根目录 `work.html`。它代表“单个 HTML 应用使用本机存储”的交互形态，不代表最终安全沙箱或发布包格式。
> **目标读者**：桌面客户端、产品、模板 SDK、市场、支付授权与安全审核工程师。

---

## 1. 产品目标

桌面客户端允许用户在桌面端设置中调整左侧栏，并把本地 HTML 应用作为一等侧栏入口。侧栏展示偏好随用户账号联网同步，网页端不提供侧栏自定义能力。

首批内置两个预设模板：

1. **个人工作台**：参考 `work.html`，用于目标、任务、项目和个人工作数据管理。
2. **个人财务记账簿**：用于本机个人收支记录、分类、汇总和 Markdown 备份。

这些模板的数据只保存在当前设备，不上传平台、不参与账号同步，也不进入公司服务端数据库。模板应能导入和导出 Markdown，便于用户备份、迁移和审阅。

未来开发者可以按照稳定模板接口开发新模板，并通过市场免费发布或出售给其他用户。

## 2. 当前实现结论

服务端 v1 已提供账号级侧栏配置、revision/ETag 冲突控制、受管 Logo、模板目录、版本包、截图、审核发布和 entitlement 下载门禁。机器契约位于 `server/openapi/desktop-client-v1.yaml`，客户端说明位于 `docs/AI_DIRECT_DESKTOP_CLIENT_API_V1.md`。

当前仓库仍没有桌面模板管理器、模板 SDK、Markdown 桥接或本地模板市场安装流程的完整实现。`work.html` 仍只是本机存储交互原型：

- 尚未被桌面客户端模板管理器安装或加载。
- 尚未接入统一 Markdown 导入导出接口。
- 尚未运行在隔离的桌面模板沙箱中。
- 尚无模板清单、截图、版本、签名、授权或升级契约。

因此本规格是后续开发必须遵守的产品与安全契约，不代表当前客户端已经支持这些能力。

## 3. 左侧栏自定义

### 3.1 设置入口

桌面端设置新增“侧栏与本地模板”页面，至少提供：

- 调整侧栏条目顺序。
- 修改可定制条目的显示文案。
- 修改可定制条目的 Logo/图标。
- 添加已安装的本地 HTML 模板到侧栏。
- 从侧栏移除模板入口，但不因此删除模板数据。
- 恢复默认侧栏配置。
- 打开模板目录。
- 查看每个模板的本地数据占用、版本和授权状态。

排序应支持拖拽和键盘操作；每次变更立即保存到当前设备，并提供撤销或恢复默认值能力。

### 3.2 稳定身份与展示配置分离

每个侧栏条目必须有不可变的 `itemId` 和可修改的展示配置：

- `itemId`：系统路由或模板安装实例的稳定身份。
- `order`：排序值。
- `label`：用户自定义文案。
- `icon`：内置图标 ID 或经客户端复制管理的本地图片资源。
- `visible`：是否显示。

修改文案或 Logo 不能改变真实路由、权限或模板身份。业务逻辑不得通过用户可修改的文案判断当前功能。

### 3.3 系统条目保护

- 登录、设置、安全更新、账号退出等关键入口不能被模板覆盖或伪装。
- 用户可以调整普通功能顺序，但关键设置入口必须始终可达。
- 自定义 Logo 不接受远程 URL；客户端必须把用户选择的本地图片复制到受管理目录并校验格式、尺寸和大小。
- 模板不能修改其他侧栏条目，也不能自行把自己固定到侧栏顶部。

### 3.4 配置作用域与联网同步

侧栏配置属于用户账号级桌面偏好，必须联网同步。同步内容包括：

- 普通侧栏条目的顺序、显示/隐藏状态和自定义文案。
- 用户自定义 Logo/图标及其受管理资源引用。
- 已选择加入侧栏的模板 ID、侧栏位置、自定义文案和 Logo。
- 用户恢复默认配置产生的最新配置版本。

公司用户和个人用户使用同一套账号级同步规则。未来如增加公司统一侧栏策略，必须采用“公司默认值 + 用户账号覆盖”的独立策略层，不能直接覆盖用户偏好，也不能改变本规格的模板业务数据仅本地边界。

用户在另一台电脑登录同一账号后，桌面客户端必须从服务端拉取并恢复侧栏配置。客户端离线时使用最近一次本地缓存，重新联网后再同步。

侧栏同步与模板业务数据严格分离：

- 个人工作台中的目标、任务、项目等数据仍只保存在创建它们的设备。
- 个人财务记账簿中的账目、分类、金额和备注仍只保存在创建它们的设备。
- 不得因为同步侧栏入口而上传 `localStorage`、IndexedDB、Markdown 备份或模板运行数据。
- 用户需要迁移模板业务数据时，必须通过本规格定义的 Markdown 导出和导入明确完成。

当同步配置引用的模板在新设备尚未安装时，桌面客户端应显示“待安装/恢复模板”状态并提供安装入口；安装完成前不能创建空模板并暗示业务数据已同步。付费模板仍需验证账号授权，但授权校验不得读取模板业务数据。

用户自定义 Logo 如需跨设备保持一致，客户端应把经过格式、尺寸和大小校验的图标作为独立偏好资源同步；禁止把任意本地绝对路径当作可跨设备 Logo 值。

### 3.5 同步一致性与隐私

- 服务端以“用户 ID + 配置版本”保存桌面侧栏偏好，不能按设备覆盖成多个互不相干的真值。
- 每个侧栏条目以稳定 `itemId` 合并；同步不能通过可修改文案识别条目。
- 写入携带配置版本或 ETag，服务端拒绝静默覆盖更新后的配置；客户端应执行条目级合并或提示用户选择版本。
- 本地缓存必须按登录账号隔离；共享电脑退出账号后，下一位用户不能读取上一位用户的侧栏偏好。
- 服务端同步数据不得包含模板业务内容、模板存储快照或本地文件绝对路径。
- 删除账号或关闭偏好同步时的服务端清理与本地保留策略，应在账号数据删除规范中统一处理。

### 3.6 网页端边界

网页端不提供左侧栏自定义功能：

- 网页设置中不显示侧栏排序、Logo、文案或模板入口配置。
- 网页端不能创建、修改、删除或覆盖桌面侧栏配置。
- 网页导航继续使用平台固定的信息架构，不读取桌面侧栏顺序或自定义文案进行渲染。
- 本地 HTML 模板只在桌面客户端运行，网页端不能打开其运行实例，也不能读取其本机数据。
- 服务端接口必须校验桌面客户端允许的调用方和用户身份，不能只依赖网页端隐藏按钮来阻止写入。

未来即使网页端提供“查看桌面设备”能力，也只能展示必要的设备/同步状态，不能把桌面侧栏编辑能力扩展到网页端，除非产品规格明确变更。

## 4. 本地 HTML 模板定义

### 4.1 模板形态

模板是可离线运行的本地 HTML 应用，主要入口为 `index.html`。模板可以像 `work.html` 一样把 HTML、CSS 和 JavaScript 写在一个文件中，也可以引用模板包内的相对静态资源。

模板不得依赖远程 CDN、远程脚本、远程字体或运行时网络 API 才能完成核心功能。

模板安装包至少包含：

```text
<template-id>/
  manifest.json
  index.html
  screenshots/
    01.png
  assets/                # 可选，本地 CSS/JS/图片/字体
```

`index.html` 是模板应用本体；`manifest.json` 和截图是桌面端选择器、升级器、市场和安全审核所需的旁车元数据。内置模板也使用同一包格式，不做只对官方模板有效的私有接口。

### 4.2 模板清单

`manifest.json` 至少包含：

```json
{
  "schemaVersion": 1,
  "id": "com.example.personal-workbench",
  "name": "个人工作台",
  "description": "管理个人目标、任务和项目进度。",
  "version": "1.0.0",
  "entry": "index.html",
  "author": {
    "name": "Example Developer",
    "publisherId": "publisher-id"
  },
  "screenshots": ["screenshots/01.png"],
  "dataSchemaVersion": 1,
  "capabilities": ["local-storage", "markdown-import", "markdown-export"]
}
```

约束：

- `id` 在市场和本机安装目录中稳定且唯一。
- `name` 和 `description` 必填。
- `screenshots` 必须为 1–4 张本地图片。
- `entry` 必须解析到模板安装目录内部，禁止 `..` 路径逃逸。
- `capabilities` 使用白名单；未声明或未批准的能力不可用。
- 模板升级不能通过更换 `id` 访问其他模板的数据。

## 5. 模板选择与安装体验

桌面端模板选择器必须展示：

- 模板名称。
- 简短介绍。
- 1–4 张截图，可左右查看和放大预览。
- 作者/Publisher。
- 版本与更新时间。
- 免费或价格信息。
- 本地能力声明。
- 安全审核和签名状态。
- 安装后数据仅保存在本机的明确提示。

安装前必须说明模板是否为官方预设、第三方免费模板或第三方付费模板。付费只控制下载和使用授权，不能改变模板的本地数据原则。

模板安装成功后由用户决定是否立即加入侧栏及其显示位置、文案和 Logo。

## 6. 首批预设模板

### 6.1 个人工作台

- 参考仓库根目录 `work.html` 的单页交互方式。
- 支持目标、任务、子任务、项目、进度和用户自定义文案。
- 状态只写入该模板实例的本地存储。
- 必须补充符合本规格的 Markdown 导入、导出适配器。
- 正式内置前必须迁入受管理模板目录，不能从仓库工作目录直接加载。

### 6.2 个人财务记账簿

- 支持收入、支出、分类、日期、备注和本地汇总。
- 数据只保存在该模板实例的本地存储。
- 默认不连接银行、支付平台、云端同步或第三方统计服务。
- 必须支持完整 Markdown 导出和受校验的 Markdown 导入。
- UI 明确提示其为个人记录工具，不替代专业会计、税务或审计软件。
- 金额计算使用整数最小货币单位或十进制定点表示，禁止直接以二进制浮点数作为持久化金额真值。

## 7. 本机数据与隔离

### 7.1 仅本机存储不变量

1. 模板运行数据不得上传 ClawHub、公司 API、分析服务或模板开发者服务器。
2. 模板运行时默认禁止 `fetch`、`XMLHttpRequest`、`WebSocket`、WebRTC 和远程资源加载。
3. 禁止 Node.js 集成、任意文件系统访问、Shell、子进程、剪贴板读取和系统凭据访问。
4. 桌面容器必须启用沙箱和上下文隔离，模板不能获取 Electron 主进程对象。
5. 模板只能通过受限桥接 API 请求导入、导出、重置和查询自身元数据。
6. 遥测只能记录模板安装、启动或崩溃等不含业务内容的事件；不得读取模板内部数据生成遥测。

“仅本地”指数据不离开当前设备，不代表任意本地 HTML 都可信。第三方模板仍必须经过包扫描、签名验证和运行时隔离。

### 7.2 每模板、每实例隔离

不能直接用共享 `file://` Origin 加载所有模板，否则不同模板可能共享或读取同一 `localStorage`。

桌面客户端应为每个模板安装实例提供独立 Origin 或独立持久化 partition，例如：

```text
claw-template://<installation-id>/index.html
```

模板的 `localStorage`、IndexedDB 和缓存必须按安装实例隔离。卸载模板时默认保留数据并询问用户；只有用户明确选择“同时删除本地数据”才清理对应存储分区。

### 7.3 数据目录与模板目录分离

模板代码和用户数据必须分开：

- 模板代码可以升级、回滚或重新安装。
- 用户数据不能因模板升级被覆盖。
- 数据迁移失败时回滚模板版本并保留迁移前备份。

禁止模板把业务数据写进自己的安装目录。

## 8. Markdown 导入与导出

### 8.1 稳定桥接接口

桌面客户端预留版本化接口 `window.clawTemplate`。模板通过注册适配器声明如何把内部状态转换为 Markdown，以及如何把 Markdown 转换为内部状态。

概念接口：

```ts
interface ClawTemplateBridgeV1 {
  getContext(): Promise<{
    templateId: string;
    installationId: string;
    locale: string;
  }>;
  registerDataAdapter(adapter: {
    exportMarkdown(): Promise<string>;
    previewImport(markdown: string): Promise<ImportPreview>;
    applyImport(markdown: string, mode: "merge" | "replace"): Promise<ImportResult>;
  }): void;
  requestExport(options?: { suggestedName?: string }): Promise<void>;
  requestImport(): Promise<void>;
}
```

最终实现可以调整具体 TypeScript 形态，但必须保持：版本化、最小权限、只能操作当前模板实例、导入先预览后确认。

### 8.2 导出要求

- 导出文件扩展名为 `.md`，UTF-8 编码。
- Markdown 顶部包含机器可读但可人工审阅的 frontmatter：模板 ID、模板版本、数据 schema 版本、导出时间。
- 正文应尽量保持人类可读，不能只输出不可读的 Base64 或单行 JSON。
- 导出由桌面主进程显示保存对话框；模板不能自行指定任意系统路径。
- 默认导出全部业务数据，也允许模板提供经过用户明确选择的范围导出。

### 8.3 导入要求

- 只接受用户主动选择的 `.md` 文件。
- 导入前校验模板 ID、schema 版本、文件大小和内容结构。
- 必须先展示导入预览，包括新增、覆盖、跳过和错误数量。
- 用户明确选择 `merge` 或 `replace` 后才能写入。
- `replace` 前自动创建本机备份；导入失败不得破坏原数据。
- Markdown 中的 HTML、脚本、链接和图片一律作为不可信内容处理，不能执行脚本或自动发起网络请求。

## 9. 模板目录

桌面客户端使用 Electron `app.getPath('userData')` 或等价平台 API 获取实际用户数据根目录，模板目录固定为：

```text
<desktop-user-data>/workspace-templates/
```

典型默认位置：

```text
Windows: %APPDATA%\iClawStore\workspace-templates\
macOS:   ~/Library/Application Support/iClawStore/workspace-templates/
Linux:   ${XDG_DATA_HOME:-~/.local/share}/iclawstore/workspace-templates/
```

应用名称或安装渠道可能导致实际根目录不同，因此不能只在文档中写死路径。桌面端设置必须：

- 显示当前设备解析后的绝对模板目录。
- 提供“复制路径”和“打开模板目录”。
- 对公司用户显示同样信息，不因公司身份隐藏目录。
- 明确提示不要在模板运行或升级过程中手工覆盖文件。

推荐目录结构：

```text
workspace-templates/
  installed/
    <template-id>/
      <version>/
        manifest.json
        index.html
        screenshots/
        assets/
  downloads/
  quarantine/
  backups/
```

模板运行数据不放在该目录，应保存在桌面运行时按 `installationId` 隔离的数据分区中。

## 10. 模板扩展与开发者接口

### 10.1 扩展原则

后续新增预设模板不得修改桌面侧栏核心代码。模板管理器通过清单发现模板，通过稳定桥接 API 提供受限能力，通过统一安装记录生成侧栏入口。

新增模板的标准流程：

1. 创建模板包及 `manifest.json`。
2. 使用本地模板开发工具校验清单、截图、离线资源和 Markdown 适配器。
3. 在隔离沙箱中预览。
4. 打包并签名。
5. 作为官方预设、本地开发模板或市场模板安装。

应预留以下版本化能力：

- 模板发现与清单校验。
- 安装、启用、停用、卸载、升级和回滚。
- 本地数据 schema 迁移。
- Markdown 导入导出适配器。
- 侧栏入口注册。
- 模板截图和详情展示。
- 授权状态查询，但不向模板暴露支付凭据。

### 10.2 开发模式

桌面设置可以提供“开发者模式 → 从本地目录加载”，但必须：

- 明确标记为未签名开发模板。
- 默认使用与正式模板相同的网络和系统权限限制。
- 不允许开发模式模板伪装成官方模板。
- 不允许把仓库任意 HTML 自动视为已安装模板；`work.html` 需要打包后才能进入正式模板列表。

## 11. 模板市场与出售

开发者可以发布免费或付费模板。市场中的模板是独立产品类型，不应伪装成普通 Skill 或拥有普通 Skill 不具备的桌面权限。

发布至少需要：

- 稳定模板 ID、名称、介绍和版本。
- 1–4 张真实模板截图。
- 作者/Publisher 身份。
- 价格、许可证和支持信息。
- 完整离线安装包与内容哈希。
- 支持的桌面客户端版本和数据 schema 版本。
- 自动安全扫描与人工审核状态。
- Markdown 导入导出能力声明。

付费授权边界：

- 平台服务端只保存商品、订单、授权和安装包元数据。
- 用户模板业务数据仍只在本机，不能作为授权校验的一部分上传。
- 客户端可以短时缓存授权，允许合理的离线使用；不能要求模板每次打开都联网。
- 开发者不能在模板中自行实现绕过平台的支付页面、远程许可证服务器或隐蔽遥测。
- 退款、撤架或开发者封禁不能远程删除用户本地业务数据；已安装代码的继续使用策略由市场许可证另行定义。

## 12. 更新、迁移与恢复

- 模板代码版本和数据 schema 版本独立管理。
- 升级前备份当前模板数据。
- 数据迁移必须按版本逐级执行且可重复检测。
- 升级失败时回滚代码版本并恢复数据备份。
- 模板更新不能重排用户侧栏、覆盖用户自定义文案或 Logo。
- 模板卸载后重新安装时，应询问是否恢复保留的本地数据。
- 用户必须始终可以在不启动模板代码的情况下导出最近一次可用备份。

## 13. 验收标准

1. 用户能在桌面设置中调整普通侧栏条目顺序、Logo 和文案，并恢复默认值。
2. 侧栏顺序、显示状态、文案、Logo 和模板入口选择保存到用户账号；同一账号在另一台电脑登录后可以恢复。
3. 离线修改可以保存在本机，重新联网后按配置版本安全合并，不静默覆盖较新的远端修改。
4. 网页端没有侧栏自定义入口，也不能通过网页请求修改桌面侧栏配置。
5. 用户能把已安装模板加入或移出侧栏，移出侧栏不会删除数据。
6. 新设备恢复了模板侧栏入口但尚未安装模板时，明确显示待安装状态，不声称模板业务数据已同步。
7. 内置“个人工作台”和“个人财务记账簿”均可完全离线运行。
8. 两个内置模板的数据均只保存在当前设备，并能导出为可读 Markdown；侧栏同步请求不包含这些业务数据。
9. Markdown 导入必须先预览，再由用户选择合并或替换；失败不损坏原数据。
10. 模板选择器展示名称、介绍和 1–4 张截图。
11. 设置页显示当前设备模板目录的绝对路径，并支持复制和打开目录。
12. 新模板可以仅通过标准模板包和稳定接口被发现、安装并加入侧栏，不修改侧栏核心代码。
13. 不同模板及同一模板的不同安装实例不能读取彼此的 `localStorage` 或 IndexedDB。
14. 模板不能联网、访问 Node/Electron、任意文件系统、Shell 或系统凭据。
15. 第三方开发者可以发布免费或付费模板，购买授权不上传模板业务数据。
16. 模板升级失败可以回滚，用户本地数据和侧栏个性化配置不丢失。

## 14. 后续实现模块边界

建议按职责拆分，而不是把所有逻辑堆进桌面设置页面：

- `SidebarConfigurationService`：稳定条目、排序、文案、Logo 和恢复默认值。
- `SidebarPreferenceSync`：账号级配置版本、跨设备拉取/推送、条目级冲突合并和用户缓存隔离。
- `TemplateRegistry`：发现、清单解析、版本选择和安装记录。
- `TemplatePackageVerifier`：哈希、签名、路径、离线依赖和安全扫描。
- `TemplateRuntimeHost`：隔离 Origin/partition、网络拦截和受限桥接。
- `TemplateDataPortability`：Markdown 导入、导出、预览和备份。
- `TemplateUpdater`：升级、数据迁移、失败回滚。
- `TemplateMarketplaceAdapter`：商品详情、购买授权和安装包获取。

数据流必须保持单向：模板只能通过受限桥接请求宿主操作；宿主不能通过抓取模板 DOM 猜测业务数据结构。Markdown 序列化职责属于模板适配器，文件选择、路径访问、备份和原子写入职责属于桌面宿主。
