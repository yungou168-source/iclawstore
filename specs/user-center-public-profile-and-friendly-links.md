# 用户中心、公开资料与友情链接约束

> **状态**：当前实现约束
> **范围**：`/dashboard`、`/settings`、`/profile/$slug`、`/recruit-ai`、站点页脚和后台友情链接管理

## 用户中心职责

`/dashboard` 是登录用户的账户工作台，不只是已发布技能列表。页面必须提供以下稳定入口：

- 个人资料与头像设置；
- 组织资料与组织头像设置；
- 当前用户的免登录公开介绍页；
- AI 员工公开目录；
- 钱包、账单与开发者收益；
- 我的收藏；
- 开发者申请、名下 AI 员工列表和创建入口。

开发者状态必须由服务端身份派生，不允许客户端提交任意用户 ID 代替当前用户。当前首期申请即时批准；如果后续改为人工审核，应扩展明确的 `pending/approved/rejected` 状态机，而不是仅靠页面隐藏按钮。

## 公开资料边界

公开资料后缀在 `users.profileSlug` 中唯一保存，通过 `by_profile_slug` 索引读取。公开页使用一次性 `ConvexHttpClient.query()` 加载用户资料，不建立响应式订阅。

公开页只可返回明确筛选后的用户字段，以及 AI 员工公开目录接口返回的已发布、可用条目。不得泄露邮箱、手机号、身份令牌、私有 Agent 版本、内部审核记录或钱包数据。

头像二进制保存在 Convex Storage；用户和发布者文档只保存 Storage ID 与可渲染 URL。上传完成后必须校验 MIME 类型和 5 MB 大小上限。组织头像更新必须再次校验当前用户的组织管理权限。

## 招聘目录登录一致性

`/recruit-ai` 是公共发现页面。登录状态可以增加招聘操作能力，但不能移除或替换公开 AI 员工列表。目录读取失败时页面应保留明确错误或既有静态目录降级，不得因为用户已登录而显示空白目录。

## 友情链接数据边界

友情链接是运营配置，属于 MySQL `friendly_links` 表，不属于 Convex 用户、发布者或技能数据。

- 公共页脚通过单次 HTTP 请求读取最多 100 条已启用链接，按 `sortOrder`、`id` 排序。
- 管理端最多读取 500 条，只有 Fastify 身份桥确认的 `admin` 可新增、编辑、启停和删除。
- 服务端只接受 `http:` 或 `https:` URL；前端校验不能替代服务端校验。
- 页脚保留版本内默认链接作为迁移/接口发布窗口的只读降级，API 成功返回空列表时应尊重管理员配置并显示为空。
- 管理写入保留创建人与最后更新人，方便后续接入统一审计投影。

## 管理后台入口与权限

友情链接管理是管理员后台的一等模块，固定入口为 `/management?view=friendly-links`。导航项和页面渲染都必须只向 `admin` 开放；不能因为 `moderator` 可以进入其他管理页面，就允许其调用友情链接写接口。服务端权限判断是最终边界，前端隐藏入口仅用于用户体验。

新增、更新、启停和删除均通过 Fastify 身份桥读取当前操作者，不接收客户端提供的任意操作者 ID。公共读取端点保持匿名可访问，且不得返回创建人、更新人或其他内部审计字段。

## 迁移与发布顺序

`20260819_friendly_links` 是扩展式迁移：只新增表和默认数据，不修改或删除既有字段。Prisma schema 必须同步声明 `friendly_links`，避免迁移 SQL 与数据模型长期漂移。

生产迁移只能在注入目标环境 `DATABASE_URL` 的发布环境执行。没有该变量、无法读取 `prisma migrate status`，或目标数据库身份不明确时，必须停止迁移，不得把“schema 校验通过”等同于“生产迁移已完成”。

生产发布顺序必须为：

1. 对目标数据库执行 `prisma migrate deploy`；
2. 发布包含友情链接 API 的后端；
3. 发布前端；
4. 验证匿名页脚读取、管理员 CRUD、用户中心入口和公开资料页。

如果迁移未完成，后端友情链接查询会失败，但前端页脚仍显示版本内默认链接；管理员模块必须视为不可用，不得伪造保存成功。
