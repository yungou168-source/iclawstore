# Web 文案国际化与覆盖门禁

> **状态**：迁移进行中；本文件定义完成条件和门禁，不表示全站已完成双语覆盖。
> **适用范围**：`src/routes/**`、`src/components/**` 中面向用户渲染的文案。

## 目标与职责

- `src/lib/i18n/translations.ts` 是 `zh-CN` 与 `en` 用户文案的唯一来源；两种语言的键与插值变量必须完全一致。
- 页面与组件只负责选择翻译键、传递插值和按 locale 格式化日期/金额；不得在 UI 中维护局部双语对象或根据 `locale` 拼接用户文案。
- API 状态码、路由、ID、协议值和服务端返回的原始错误保持原语义；需要展示时在 UI 边界映射为翻译键，不能改变请求或状态机。

## 硬编码扫描门禁

完成全站迁移后，新增的扫描测试必须覆盖以下渲染位置：

- JSX 子文本；
- `aria-label`、`title`、`placeholder`、`alt`；
- Dialog、Sheet、Toast、浏览器提示与空态/加载态/错误态；
- 表格标题、操作项、统计标签和按钮文案。

扫描失败必须报告**文件、行号、命中模式和原因**。门禁不得使用宽泛 allowlist 掩盖遗漏，尤其禁止为 AI Direct 或 `/management` 增加豁免。

允许最小化例外的仅限非用户文案：路由与 URL、DOM/测试选择器、稳定协议枚举、品牌/第三方专名、正则表达式、测试夹具、服务端原始错误，以及法定登记标识。每个例外必须记录文件、匹配模式和理由；例外应随源码删除而删除。

## 验收顺序

1. 完成 `src/routes/**` 与 `src/components/**` 的用户可见文案迁移；
2. 运行翻译键/插值契约和硬编码扫描门禁；
3. 运行相关组件与页面测试、格式化检查和静态门禁；
4. 仅在上述验证完成后，处理可回滚构建产物目录并执行前端构建；
5. 生产发布仍依赖数据库、认证、支付与服务端验收，不因前端文案测试通过而自动发布。

当前 `ci:static`、`ci:types-build`、完整扫描门禁和前端构建均尚未因本轮文案工作而通过；不得将本文件的阶段性记录表述为发布完成。
